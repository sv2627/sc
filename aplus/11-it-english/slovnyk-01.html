1 · KEY WORDS 7.1–7.6 · дослівно з книжкис. 145–157

  • program development life cycle — a series of structure step activities that are followed to produce a system. Життєвий цикл розробки програми.
  • analysis — the first stage of the program development life cycle that involves investigating the problem. Перший етап — дослідження задачі.
  • decomposition — taking a system and splitting it into smaller sub-systems, which can in turn be split into smaller sub-systems. Поділ на під-системи.
  • design — the second stage… which involves decomposition of the problem and algorithms created ready for implementation. Другий етап — проєктування.
  • structure diagram — a hierarchical diagram that shows the decomposition of a system. Показує склад, а не порядок дій.
  • flowchart — a diagrammatic representation of an algorithm. Показує порядок.
  • pseudocode — code-like statements that are used to design an algorithm but do not follow any specific language. Показує, що саме робити.
  • coding — the writing of a program using one or more programming languages. Третій етап.
  • iterative testing — testing that is carried out while the program is being developed. Тест під час розробки.
  • testing — repeated use of a system to try all different possibilities to make sure the system is fully working and cannot be broken. Четвертий етап.
  • test data — the input data that is used to test a system. Тестові дані.
  • requirements — вимоги до програми, які визначають на етапі analysis. Без записаної вимоги слово «правильно» втрачає сенс.

3 · KEY WORDS 7.7 · дослівно з книжкис. 167–171

  • totalling — statements in a program that add together a set of data to produce the total. Підсумовування — додаємо значення.
  • counting — statements in a program that record how many of something there are. Підрахунок — додаємо одиницю.
  • minimum — the smallest item in a set of data. Найменше значення набору.
  • maximum — the largest item in a set of data. Найбільше значення набору.
  • average — the mean of a set of values, the total divided by the quantity. Середнє: Total / Count.

  • Decomposition is the splitting of a system into sub-systems.
  • Algorithms can be planned using flowcharts and pseudocode.
  • All boxes lead somewhere else so that you cannot get stuck in the flowchart with nowhere to go. Обірвана стрілка — помилка, навіть якщо решта правильна.

  • Some will use ← instead of an = for assignment. Приймають обидва.
  • Your syntax doesn’t have to be perfect — it is your logic that is important. TIP книжки, с. 155.

  • Totalling is adding together the values. Counting is adding 1 to the count for each item.

7 · Questions and answers · Питання й базові відповіді

1. Identify the stages in the program development life cycle.
Analysis · design · coding · testing. There are several varieties of life cycle — cyclic, spiral, waterfall and rapid development — and all of them include these four stages.
2. Describe the process of decomposition. (Q1, с. 156)
Taking a system and splitting it into smaller sub-systems, which can in turn be split into smaller sub-systems. Each sub-problem becomes a subprogram.
3. Why decompose a problem?
Sub-problems allow the developers to identify the requirements for each component part, and then tackle these separately in the next stage.
4. What happens in the analysis stage?
The problem is explored, and the requirements of the program are identified.
5. Name the three design tools and say what each one answers.
structure diagram — what it is made of · flowchart — in what order · pseudocode — what exactly to do.
6. Describe the purpose of pseudocode. (Q8, с. 156)
Code-like statements used to design an algorithm without following any specific language, so any programmer can understand it.
7. Two students decomposed the same problem differently. Who is right?
Both. «There are lots of ways you can decompose a problem, and everyone could do it slightly differently but the solution is still valid.»
8. What is iterative testing?
Testing that is carried out while the program is being developed — each subprogram is tested as soon as it is written.
9. Name the four types of test data.
normal · abnormal · extreme · boundary.
10. What is the difference between extreme and boundary test data? (Q14)
Extreme is data on the edge of what is allowed — one value. Boundary is data on both sides of the edge — always a pair.
11. A program accepts a whole number from 10 to 100. Give the test data.
Normal — any number 10 to 100, e.g. 20, 50 · Abnormal — 9, −1, 101, "age", 12.2 · Extreme — 10 and 100 · Boundary — 9 and 10, 100 and 101.
12. Explain the difference between totalling and counting. (Q21, с. 172)
Totalling adds the value of each item to a running total: Total ← Total + Value. Counting adds 1 each time, no matter what the value is: Count ← Count + 1. For 5, 5, 5 the total is 15 and the count is 3.
13. Numbers between 20 and 200 are entered. How do you initialise Smallest and Largest? (Q22)
Smallest — something larger than 200, e.g. 201 or 9999. Largest — something smaller than 20, e.g. 19 or 0. Otherwise the first value entered never replaces the start value.
14. How do you find the average?
You need the count and the total from earlier. The average is Total / Count.
15. Where must OUTPUT stand in a totalling algorithm?
After the loop, not inside it. Inside, it would print every partial total. The initialisation, likewise, goes before the loop.
16. A program works perfectly. Is it correct?
Not necessarily. It must also meet all requirements — that is why the requirements are written down in the analysis stage.

8 · I can… · Self-evaluation checklist

  • identify the stages in the program development life cycle.
  • use decomposition to split a system into sub-systems.
  • create structure diagrams, flowcharts and pseudocode algorithms.
  • identify appropriate test data for an algorithm.
  • explain the difference between totalling and counting.
  • describe and produce algorithms that include finding the maximum, minimum and average values.
  • spot an error in a printed algorithm.
