Follow

Three algorithms, one job

Три записи. Різні слова, різні символи. Роблять вони одне й те саме.

AINPUT value1 INPUT value2 OUTPUT value1 + value2
Bvalue1 = INPUT value2 = INPUT result = value1 + value2 print(result)
Cvalue1 ← ReadLineFromUser value2 ← ReadLineFromUser Printout value1 + value2
Схема Cambridge каже прямо: «there is no defined pseudocode that everyone uses». Запис залежить від того, хто й навіщо пише.
🤔
Understand

What is the same in all three?

Подивіться на A, B і C ще раз. Знайдіть спільне — не слова, а дії.

Five similarities

Назвіть щонайменше три, потім клацніть.

  • символ присвоєння — = або ←
  • командне слово для вводу — INPUT, ReadLineFromUser
  • символ додавання — +
  • командне слово для виводу — OUTPUT, print, Printout
  • змінні, у яких зберігаються дані

Predict

Спочатку скажи, потім перевір

Це головне правило другої половини уроку. Спершу назви результат — і лише потім проходь алгоритм.

Так не працює

Пройшов алгоритм → побачив відповідь → сказав «ну я так і думав». Тут нічого не перевірено

Так працює

Сказав відповідь уголос або записав → пройшов алгоритм → порівняв. Тепер видно, чи ти справді зрозумів

Помилка в передбаченні — це не погано. Це найкорисніша хвилина уроку: саме тут стає видно, чого ти не помітив.

Algorithm A

Message depending on age

age = input("Enter your age") if age < 18: print("You are a child") else: print("You are an adult")
Ще один стиль запису — з двокрапкою і відступом. Це той самий IF / ELSE
Три частини умовного оператора: умова · код, коли true · код, коли false
Передбачте вихід для 12, 18, 45. На 18 подумайте двічі
🧮
Algorithm B

A calculator

number1 = input("Enter the first number") number2 = input("Enter the second number") calculation = input("Enter the calculation") IF calculation == "+" THEN result = number1 + number2 ELSE IF calculation == "-" THEN result = number1 - number2 ELSE IF calculation == "/" THEN result = number1 / number2 ELSE result = number1 * number2 ENDIF ENDIF ENDIF
Що станеться, якщо ввести "x" замість знака дії? Пройдіть алгоритм і подивіться.

Correct

Помилився я — чи алгоритм?

Коли передбачення не збіглося, є рівно два пояснення. Розрізняти їх — окрема навичка.

Помилка в передбаченні

Алгоритм правильний, я неуважно прочитав. Найчастіше — переплутав > і < або пропустив ELSE

Помилка в алгоритмі

Я прочитав правильно, а алгоритм робить не те, що мав би. Тоді треба знайти який саме рядок і виправити

Питання, яким це розрізняється: «а чого я взагалі чекав від цього алгоритму?» Якщо не можеш відповісти — перевіряти нічого.

Що лишається з уроку

Порядок роботи з чужим алгоритмом

1 Read — прочитати цілком, не виконуючи
2 Predict — записати очікуваний вихід
3 Follow — пройти крок за кроком із даними
4 Compare — збіглося? Ні — шукати, де саме
Цей порядок працює й далі: у 9 класі з циклами, у 10-му з псевдокодом IGCSE, і в будь-якій мові програмування.
