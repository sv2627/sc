List · доступ

Номер у квадратних дужках. З нуля

main.dart
var igry = ['Minecraft', 'Terraria', 'Stardew']; // 0 1 2 print(igry[0]); // Minecraft print(igry[2]); // Stardew print(igry.first); // Minecraft print(igry.last); // Stardew igry[1] = 'Hollow Knight'; // замінили print(igry[3]); // ПАДІННЯ: індексу 3 немає
Нумерація з нуля. У списку з трьох елементів останній номер — 2, а не 3
first і last — те саме, що [0] і [length - 1], але читається краще
Вийшов за межі — програма падає на ходу (RangeError). Dart цього не бачить заздалегідь, бо номер може бути порахований під час роботи

List · додати · 3 способи

Список росте

main.dart
List<String> spysok = ['hlib']; spysok.add('moloko'); // [hlib, moloko] spysok.addAll(['syr', 'yabluka']); // [hlib, moloko, syr, yabluka] spysok.insert(0, 'voda'); // [voda, hlib, moloko, syr, yabluka]
add — один елемент у кінець. Це 95 % випадків
addAll — одразу цілий список у кінець. Приймає список, а не елемент
insert(індекс, що) — вставити у середину. Усі, хто правіше, зсуваються
Це методи, як функції з уроку 4, тільки викликаються через крапку в самого списку: spysok.add(...)

List · прибрати · 4 способи

Список меншає

main.dart
var s = ['voda', 'hlib', 'syr', 'hlib']; s.remove('hlib'); // [voda, syr, hlib] — тільки ПЕРШИЙ hlib s.removeAt(0); // [syr, hlib] — за номером s.removeLast(); // [syr] s.clear(); // [] — порожній, але список живий
remove шукає за значенням і прибирає лише перший збіг. Решта однакових лишаються
removeAt — за номером. Не плутати: remove(0) у List<int> шукатиме значення нуль
clear робить список порожнім. Сам список нікуди не дівається — у нього можна знову класти
remove повертає true або false — чи справді щось прибрав. Немає такого елемента — просто false, без падіння

List · розмір

Скільки їх і чи є вони взагалі

main.dart
var s = ['hlib', 'moloko', 'syr']; print(s.length); // 3 print(s.isEmpty); // false print(s.isNotEmpty); // true // останній індекс — завжди length - 1 print(s[s.length - 1]); // syr if (s.isEmpty) { print('Spysok porozhniy'); }
length — без дужок. Це властивість, а не метод: s.length, не s.length()
Кількість — 3, останній індекс — 2. Різниця на одиницю, і саме на ній роблять найбільше помилок
if (s.length == 0) теж працює, але isEmpty читається як речення — і в Dart прийнято саме так

main.dart
var s = ['a', 'b', 'a', 'c']; s.remove('a'); print(s); s.removeAt(0); print(s); print(s.length); print(s.isEmpty);

List · перебір · 2 способи

Цикл нарешті має що перебирати

main.dart
var s = ['hlib', 'moloko', 'syr']; // for-in: потрібні самі значення for (String tovar in s) { print(tovar); } // for(i): потрібен ще й номер for (int i = 0; i < s.length; i++) { print('${i + 1}. ${s[i]}'); }
На уроці 3 for-in ми вже бачили — тепер зрозуміло, по чому він ходить
Правило вибору: потрібен лише елемент — for-in; потрібен номер (нумерований список, порівняння сусідів) — for(i)
Не можна прибирати елементи зі списку всередині for-in по ньому ж — Dart кине помилку прямо під час циклу

List · пошук

Чи є воно тут

main.dart
var s = ['hlib', 'moloko', 'syr']; print(s.contains('syr')); // true print(s.contains('Syr')); // false — регістр! print(s.indexOf('moloko')); // 1 print(s.indexOf('kava')); // -1 — немає if (!s.contains('kava')) { s.add('kava'); // щоб не було двічі }
contains відповідає так або ні. Це те, що частіше за все й потрібно
indexOf каже де саме. Не знайшов — повертає -1, а не падає й не повертає порожнечу
Регістр має значення: 'syr' і 'Syr' — різні рядки. Порівнюючи введене людиною, спершу приводять до одного регістру

List · порядок і вивід

Відсортувати й показати людині

main.dart
var s = ['syr', 'hlib', 'moloko']; s.sort(); print(s); // [hlib, moloko, syr] print(s.reversed.toList()); // [syr, moloko, hlib] print(s.join(', ')); // hlib, moloko, syr var ciny = [300, 50, 120]; ciny.sort(); print(ciny); // [50, 120, 300]
sort міняє сам список, а не повертає новий. Після нього старий порядок втрачено назавжди
Рядки сортуються за абеткою, числа — за величиною. Dart знає, як порівнювати і те, і те
join(', ') склеює список в один рядок — саме так список показують людині, а не як [a, b, c]
reversed сам по собі списком не є — потрібне .toList(). Це перша зустріч із таким; далі їх буде більше

Map · навіщо

Коли номер нічого не означає

main.dart
// СПИСОК: «що там під номером 1?» var slovnyk = ['widget', 'vidzhet', 'state', 'stan']; print(slovnyk[1]); // vidzhet — але чому саме 1? // MAP: «що означає widget?» Map<String, String> sl = { 'widget': 'vidzhet', 'state': 'stan', }; print(sl['widget']); // vidzhet
У Map замість номера — ключ. Ключ ти вигадуєш сам, і він щось означає
Map<String, String> читається «ключ — рядок, значення — рядок». Перший тип — ключ, другий — значення
Фігурні дужки { }, пара пишеться через двокрапку: 'kliuch': znachennia
Порядку тут немає сенсу. Питання до Map — не «який третій», а «що лежить під цим іменем»
2️⃣
Map · читати, дописувати, міняти

Один запис — один рядок

main.dart
Map<String, int> ciny = { 'hlib': 25, 'moloko': 40, }; print(ciny['hlib']); // 25 ciny['syr'] = 180; // дописали новий ciny['hlib'] = 30; // змінили наявний print(ciny); // {hlib: 30, moloko: 40, syr: 180}
Дописати й змінити — той самий рядок: map[kliuch] = znachennia. Ключа не було — зʼявиться; був — перезапишеться
Саме тому випадкова помилка в ключі не помітна: ciny['hlub'] = 30 не виправить хліб, а додасть третій запис із дивною назвою
Порожня Map — з типом, як і список:
Map<String, int> m = {};
🧹
Map · прибрати й перевірити

Чи є такий ключ

main.dart
var ciny = {'hlib': 25, 'syr': 180}; print(ciny.containsKey('hlib')); // true print(ciny.length); // 2 print(ciny.isEmpty); // false ciny.remove('syr'); print(ciny); // {hlib: 25} ciny.clear(); print(ciny); // {}
containsKey перевіряє ключ. Для значень є containsValue, але він потрібен значно рідше
remove у Map — за ключем (у List був за значенням). Одна назва, різна робота — дивись, із чим працюєш
length, isEmpty, clear — такі самі, як у List. Це не збіг: так зроблено навмисно, щоб менше запамʼятовувати
🤔
Передбач

А якщо ключа немає?

main.dart
var s = ['hlib', 'syr']; var m = {'hlib': 25, 'syr': 180}; print(m['kava']); print(s[5]);

Відповідь

Обидва рядки поводяться по-різному. Чому?

null падіння: RangeError

Map на невідомий ключ віддає null — «нічого». Програма їде далі, і помилка спливе десь пізніше

List на неіснуючий індекс — падає одразу. Бо список знає свою довжину, а Map не може знати всі ключі, яких у ній немає

Слово null запамʼятайте: на уроці 12 буде цілий урок про нього.

Map · перебір · 3 способи

Пройти по всіх записах

main.dart
var ciny = {'hlib': 25, 'syr': 180}; // 1. по ключах — найчастіше for (String k in ciny.keys) { print('$k: ${ciny[k]}'); } // 2. тільки значення for (int c in ciny.values) { print(c); } // 3. пара одразу ciny.forEach((k, v) => print('$k — $v grn'));
keys — усі ключі, values — усі значення. Мати ключ достатньо: значення завжди поруч, через ciny[k]
forEach одразу дає обидва. Тут упізнається стрілка => з уроку 4 — це та сама коротка функція
Сума значень рахується так само, як по списку: for (int c in ciny.values) suma += c;

Тримати відкритим

Уся родина на одному екрані

створити список List<String> s = ['a', 'b'];
порожній список List<int> c = [];
узяти / замінити s[0] · s.first · s.last · s[0] = 'x'
додати s.add('c') · s.addAll([...]) · s.insert(0, 'x')
прибрати s.remove('a') · s.removeAt(0) · s.removeLast() · s.clear()
скільки s.length · s.isEmpty · s.isNotEmpty
перебрати for (String x in s) · for (int i = 0; i < s.length; i++)
шукати s.contains('a') · s.indexOf('a') → -1
порядок і вивід s.sort() · s.reversed.toList() · s.join(', ')
створити Map Map<String, int> m = {'a': 1};
узяти / дописати m['a'] · m['b'] = 2
прибрати й перевірити m.remove('a') · m.containsKey('a') · m.length · m.clear()
перебрати Map for (String k in m.keys) · m.values · m.forEach((k, v) => ...)
немає такого m['нема'] → null · s[99] → падіння

Пастки

На чому спотикаються всі

1 Індекс з нуля, а довжина з одиниці. У списку з пʼяти елементів s[5] — падіння. Останній — s[4], він же s.last
2 length без дужок, а add(), sort(), clear() — з дужками. Властивість проти методу
3 remove у List — за значенням, у Map — за ключем. І в List він прибирає лише перший збіг
4 sort() псує оригінал. Він не повертає новий список — він перекладає елементи в тому самому. Потрібен старий порядок — зберігай копію заздалегідь
5 Помилка в ключі Map мовчить. m['hlub'] = 30 не виправить 'hlib', а створить новий запис. Читання ж неіснуючого ключа дає null без попередження
6 Квадратні дужки для List, фігурні для Map. [ ] — по порядку, { } — за іменем, пара через двокрапку
