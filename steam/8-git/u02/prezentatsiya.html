Git ≠ GitHub

Git — програма на цьому комп'ютері, працює без інтернету. GitHub — сайт, куди історію можна відправити. Сьогодні інтернет не потрібен.

📍
Сьогодні ми стоїмо лівіше за всі три стани. Спершу треба, щоб у папки взагалі з'явилось місце, де історія зберігатиметься.
🎯
Сьогодні

Чотири кроки за 45 хвилин

1 Відкрити стартовий комплект у редакторі — папкою, а не файлом
2 Створити репозиторій у цій папці. Одна кнопка
3 Назвати себе: ім'я та пошта автора змін. Робиться раз і назавжди
4 Навчитися читати стан файлів — Git весь час його показує
🚫
Комітів сьогодні не робимо. Це наступний урок. Сьогодні — підготувати місце й навчитися бачити, що Git про нас думає.
📂
Перше за комп'ютерами

Відкривати папку, а не файл

Це найчастіша помилка першого уроку за машинами. Git працює з папкою цілком. Якщо відкрити один файл — редактор не побачить проєкту й кнопки Git будуть неактивні.

✗ Так не треба

Двічі клацнути по index.html — відкриється один файл, решти проєкту редактор не бачить

✓ Так треба

File → Open Folder… і вибрати папку portfolio цілком. Зліва з'явиться список усіх файлів

🔎
Перевірка: у лівій колонці зверху написана назва папки великими літерами. Немає назви — відкрито файл, а не папку.
📦
Матеріал уроку

Стартовий комплект

Однаковий у всіх. Це звичайний сайт із трьох сторінок — рівно те, що весь рік будемо змінювати й зберігати в історію.

portfolio/
  ├── index.html головна
  ├── about.html про мене
  ├── works.html роботи
  ├── style.css оформлення
  └── img/ картинки
Розпакувати архів у свою папку, не залишати його в «Завантаженнях»
Хто вже має власний сайт із 6 класу — можна взяти його. Комплект однаково збережи
Назва папки — латиницею, без пробілів. Git це переживе й з пробілами, а термінал на уроці 5 — ні
🗄️
Головне поняття

Репозиторій — це папка з пам'яттю

Репозиторій — папка проєкту, у якій Git веде історію. Ніякої окремої програми, хмари чи реєстрації: це та сама папка, у якій лежать твої файли.

Було

Папка з файлами. Зберіг — старе зникло назавжди. Історії немає

Стало

Та сама папка з тими самими файлами плюс пам'ять: кожен збережений стан можна знайти й повернути

💡
Слово «репозиторій» скорочують до repo — так його називають скрізь у меню, статтях і відео.
⚙️
Як це працює

Що змінює одна кнопка

🧷
Створення репозиторію нічого не робить із твоїми файлами. Воно тільки додає порожню службову папку.
🔒
Не чіпати

Службова папка .git

Назва починається з крапки. У більшості систем це означає «прихований» — тому в провіднику її зазвичай не видно
Уся історія проєкту — усередині неї. Скопіював папку проєкту разом із .git — скопіював історію
Видалив .git — історія зникла, файли лишились. Це єдиний спосіб «розгітити» папку

Правило на весь рік

Усередину .git не заходимо руками й нічого там не правимо. Усе, що там треба, робиться командами Git.

Це не таємниця й не захист — просто там службовий формат, який легко зіпсувати випадковим збереженням.

Практика 1 Створюємо репозиторій7 хвилин
1 Розпакувати комплект у свою папку. Відкрити редактор → File → Open Folder… → вибрати portfolio
2 Ліворуч знайти третю іконку згори — Source Control (гілочка). Або Ctrl + Shift + G
3 Натиснути синю кнопку Initialize Repository
4 Готово. Список файлів на панелі має змінитися — саме це й розбиратимемо далі
🙋
Кнопки Initialize Repository немає, а замість неї пропонують «Open Folder» — значить відкрито файл, а не папку. Поверніться до кроку 1.

Перевірка

Як переконатися, що вийшло

Три ознаки. Достатньо будь-якої, але надійніше подивитись на всі три.

1 · Панель

Кнопка Initialize Repository зникла, замість неї — поле для повідомлення й список файлів

2 · Рядок унизу

У нижньому рядку редактора зліва з'явилась назва гілки — main

3 · Сама папка

Увімкнути показ прихованих файлів — у папці видно .git

⌨️
Показати приховане: Windows — у провіднику вкладка «Вигляд» → «Приховані елементи». macOS — Cmd + Shift + .
✍️
Наступний крок

Кожен запис в історії підписаний

Історія — це не просто список змін. Біля кожного запису стоїть, хто його зробив і коли. Git бере ці дані не з системи й не з облікового запису — їх треба назвати самому.

Додав сторінку контактів · Олена К.сьогодні 14:20
Виправив меню · Олена К.вчора 16:05
Перша робоча версія · Олена К.8 вересня
🧑‍🤝‍🧑
Поки проєкт твій, підпис здається зайвим. У третій темі ви працюватимете в парах в одному репозиторії — і без підпису буде не розібрати, хто що зробив.
⚙️
Як це працює

Звідки береться підпис

⌨️
Дві команди

Пишуться один раз і назавжди

Кнопки для цього немає — тільки термінал. У редакторі він відкривається Ctrl + ` або Terminal → New Terminal.

Термінал
# хто я $ git config --global user.name "Олена Коваленко" # моя пошта $ git config --global user.email "olena@school.ua" # перевірити, що записалось $ git config --global --list
--global — «для всіх моїх проєктів на цьому комп'ютері», а не тільки для цієї папки
Лапки обов'язкові, якщо в імені є пробіл. Це найчастіша помилка в цих двох рядках
Практика 2 Називаємо себе4 хвилини
⭐ Відкрити термінал і виконати обидві команди зі своїм іменем та поштою. Ім'я — справжнє, латиницею або кирилицею, як зручно
⭐⭐ Виконати git config --global --list і знайти в списку свої два рядки
⭐⭐⭐ Спробувати виконати команду без лапок — подивитись, що саме запише Git, і виправити
📮
Пошта може бути будь-яка робоча — але запам'ятайте, яку вписали. У грудні на цю саму адресу реєструватимемо GitHub.

Панель

Що показує Source Control

Після створення репозиторію панель перестала бути порожньою. Тепер це постійний звіт Git про твої файли — він оновлюється сам, щойно ти щось зберігаєш.

▸ Поле зверху — сюди пишуть повідомлення до збереження. Сьогодні не чіпаємо
▸ Changes — список файлів, у яких є щось незбережене в історію
▸ Буква праворуч від файлу — його стан. Ось це найважливіше
🔤
Головне на сьогодні

Дві букви, які треба впізнавати

index.htmlU
about.htmlU
style.cssM

Так це виглядає на панелі

U — untracked

Поза наглядом. Git бачить файл, але жодного його стану ще немає в історії. Так виглядають усі файли одразу після створення репозиторію

M — modified

Змінений. Файл уже є в історії, але з того часу його правили. Ця буква з'явиться в нас тільки на наступному уроці

🤔
Передбач

Скільки файлів буде в списку?

Стартовий комплект: index.html, about.html, works.html, style.css і папка img/ з двома картинками. Щойно створили репозиторій, більше нічого не робили.

Скільки рядків покаже Changes і з якою буквою?

Порахуйте самі. Клацніть, щоб перевірити.

Шість. Усі з буквою U.

Чотири файли в корені плюс дві картинки всередині img/: Git рахує файли, а не папки. Порожня папка в списку не з'явиться взагалі — Git її просто не помічає.

І жодного M: щоб файл став «зміненим», він спершу має потрапити в історію.

👁️
Не плутати

«Бачить» — це ще не «зберігає»

Найпоширеніше непорозуміння першого тижня: здається, що після Initialize Repository файли вже в безпеці. Це не так.

Що Git уже робить

Стежить за папкою й показує, що в ній змінилося. Це відбувається саме, без жодних команд

Чого Git ще не зробив

Не зберіг нічого. В історії порожньо. Видалиш файл зараз — повертати нема звідки

📅
Саме тому наступний урок називається «Збереження змін». Буква U у всіх файлів — це список того, що ще жодного разу не потрапило в історію.

⭐ Відкрити index.html, змінити текст заголовка, зберегти. Подивитись, що сталося зі списком
⭐⭐ Створити новий файл contacts.html і знайти його на панелі. Потім видалити — і знайти, що змінилось
⭐⭐⭐ Створити порожню папку в проєкті. Пояснити сусідові, чому Git її не показує

Якщо щось пішло не так

Три збої, які трапляються сьогодні

Кнопки немає

Відкрито файл, а не папку. File → Open Folder… і вибрати папку проєкту

Репозиторій не там

Створили не в portfolio, а в «Завантаженнях» чи на робочому столі. Видалити .git і зробити наново у правильній папці

Репозиторій у репозиторії

Папка проєкту лежить усередині іншої, де вже є .git. Винести проєкт назовні

🧯
Усі три лікуються однаково: видалити папку .git і почати спочатку. Твої файли від цього не постраждають — сьогодні в історії ще нічого немає.
🔤
Словник

Слова, які лишаються англійською

repository — сховище. Папка проєкту з історією. Скорочено repo
initialize — «створити з нуля». Те, що робить кнопка
source control — керування вихідним кодом. Назва панелі
untracked — поза наглядом. Буква U
modified — змінений. Буква M
config — налаштування. Команда, якою назвали себе

Підсумок

Що є після другого уроку

Зроблено

  • проєкт відкрито папкою в редакторі
  • у папці є репозиторій і .git
  • ім'я та пошта автора налаштовані
  • панель Source Control читається

Наступного разу

  • перший запис в історії
  • що таке «підготувати зміну»
  • як писати повідомлення, щоб через місяць зрозуміти
  • кілька змін — кілька окремих записів
Домашнього завдання немає. Але папку portfolio не видаляйте — з нею працюємо весь рік.
