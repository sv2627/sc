Сьогодні

Обіцяне минулого уроку

На минулому уроці я сказав: «комітів сьогодні не робимо, це наступний урок». Наступний урок — сьогодні.

1 Три стани файлу — і чому їх саме три
2 Перший запис в історії. Дві дії: підготувати й зберегти
3 Повідомлення — як написати так, щоб через місяць зрозуміти
4 Кілька змін — кілька окремих записів. Це і є назва уроку
💾
Головне непорозуміння

«Зберегти» — це два різні збереження

Ctrl + S

Зберегти файл на диску. Те, що ви робите весь час у редакторі.

Старий вміст при цьому зникає назавжди. Ніякої історії тут немає

commit

Зберегти стан в історію. Окрема дія, окремою кнопкою.

Створює запис, до якого можна повернутись через місяць і через рік

⚠️
Одне не замінює інше. Спершу Ctrl + S — інакше Git не побачить змін узагалі. Потім commit — інакше вони не потраплять в історію. Обидва щоразу.
🚦
Ядро курсу

Три стани, у яких може бути файл

1 · Змінений

modified

Ви щось правили й натиснули Ctrl+S. Git це помітив і показує в Changes

2 · Підготовлений

staged

Ви сказали Git: «оцю зміну я хочу зберегти». Вона перейшла в Staged Changes

3 · Збережений

committed

Зміна в історії. Панель чиста. Тепер її можна знайти й повернути

🤔
Питання, яке ставлять усі: навіщо середній стан? Чому не зберігати одразу? Відповідь — за два слайди, і саме в ній суть уроку.
⚙️

Відповідь на питання

Навіщо потрібен середній стан

Уявіть, що ви за годину зробили три різні речі: виправили помилку в тексті, поміняли колір і додали нову сторінку. Якщо зберігати все одразу, вийде один запис «щось поміняв».

Без add

Один запис, у якому змішано три різні справи. Через місяць не розібрати, що там було

Повернути одну з трьох змін — неможливо

З add

Ви обираєте, що саме входить у цей запис. Три справи — три записи

Кожен можна знайти, прочитати й повернути окремо

🧺
Як кошик у магазині: add — покласти в кошик, commit — пробити чек. Що не поклав — те й не пробилось.

Де це в редакторі

Дві кнопки на панелі Source Control

Staged Changes
  index.htmlA
Changes
  style.cssM

Так панель виглядає, коли один файл підготовлено, а другий ні

Плюс біля файлу — це і є add. Файл переїде вгору, у Staged Changes
Мінус у Staged — забрати назад. Нічого страшного не станеться
Поле зверху — повідомлення. Далі синя кнопка ✓ Commit
🔤
Нова буква: A — added, файл уперше додано в історію. Букви U більше не буде — вона перетворюється на A одразу після плюса.
🤔
Передбач

Що потрапить у запис?

1 Змінили index.html, зберегли
2 Натиснули + біля нього
3 Змінили index.html ще раз, зберегли
4 Натиснули ✓ Commit

Друга правка потрапить у запис?

Подумай, потім клацни.

Ні. У записі буде тільки перша правка.

add робить знімок файлу саме в ту мить, коли ви натиснули плюс. Усе, що зробили після, — це вже нова зміна.

Тому файл з'явиться на панелі двічі: у Staged Changes (перша правка) і в Changes (друга).

Це збиває з пантелику всіх на першому тижні. Правило просте: змінив після add — додай ще раз.

Приклад — робимо разом
1. Ctrl+S — зберегти файл 2. плюс біля файлу — переїхав у Staged Changes 3. написати повідомлення в поле зверху 4. ✓ Commit — панель стала чистою
Тепер самостійно
  • Зробити перший коміт усього стартового комплекту. Повідомлення — «Перша версія сайту»
  • Перевірити: панель чиста, жодного файлу в списку
  • Змінити заголовок у index.html, зберегти. Знайти букву M
  • Зробити другий коміт із цією зміною
  • ⭐⭐ Натиснути плюс, потім мінус — забрати файл назад із Staged. Подивитись, куди він переїхав
  • ⭐⭐⭐ Відтворити ситуацію зі слайда 9: add, потім змінити ще раз. Знайти файл у двох місцях одночасно

Повідомлення — це не формальність

Оціни

Яке повідомлення нікуди не годиться?

А. Додав футер із контактами
Б. Виправив помилку
В. Поміняв колір кнопок на зелений
Г. Оновив index.html

Два погані. Які саме й чому?

Обери, потім клацни.

Б — «Виправив помилку». Яку? Їх у проєкті може бути двадцять. Через місяць це нічого не скаже.

Г — «Оновив index.html». Те, що змінився саме index.html, Git і так знає. Повідомлення має казати те, чого Git не знає — навіщо.

А і В хороші: зрозуміло, що з'явилось у проєкті й що шукати, якщо доведеться повертатись.

Правило: не пишіть назви файлів у повідомленні. Пишіть, що змінилось у проєкті.

Що станеться на уроці

Commit без повідомлення відкриє дивний файл

Натиснули ✓ Commit, а поле порожнє — VS Code відкриє вкладку COMMIT_EDITMSG із текстом англійською. Виглядає страшно, насправді ні.

1 Це просто інший спосіб ввести повідомлення. Напишіть його першим рядком цього файлу
2 Збережіть (Ctrl+S) і закрийте вкладку. Коміт зробиться
3 Передумали — просто закрийте, нічого не пишучи. Коміта не буде, нічого не зламається
🧯
Простіше цього уникати: спершу пишемо повідомлення в поле, потім тиснемо Commit. Саме в такому порядку.

Назва уроку

Одна зміна — один запис

Головне правило на весь рік. Зробили дві різні справи — це два коміти, а не один.

Один запис на все
✗ «Робота за 15 вересня» · виправив меню · додав три фото · поміняв кольори · дописав контакти
Чотири записи
✓ Виправив посилання в меню ✓ Додав три фото на головну ✓ Поміняв кольори на темні ✓ Дописав контакти в футер
🎯
Перевірка: якщо в повідомленні хочеться написати «і» — це, найімовірніше, два коміти.

Якщо щось пішло не так

Чотири біди сьогоднішнього уроку

Кнопка Commit сіра — у Staged Changes порожньо. Спершу плюс, потім коміт
Файл лишився в Changes після коміта — ви змінили його після того, як натиснули плюс
Відкрився COMMIT_EDITMSG — повідомлення було порожнє. Напишіть перший рядок і закрийте
Git просить назвати себе — git config не спрацював. Повторіть із уроку 2
🧭
Спільне в усіх чотирьох: нічого не зламалось. У Git майже неможливо втратити роботу — усе, що потрапило в історію, лишається там назавжди.
🎒
Закінчив раніше?

Банк завдань — бери будь-яке

П'ять комітів поспіль. П'ять маленьких змін, кожна окремим записом із нормальним повідомленням
Порожня папка. Створити папку без файлів і перевірити, чи можна її закомітити
Видалення. Видалити файл, який уже в історії. Подивитись, яка буква з'явиться на панелі
Перейменування. Перейменувати файл і подивитись, як це побачить Git
Рецензія. Прочитати історію сусіда й сказати, які три повідомлення варто переписати
Англійською. Зробити три коміти з повідомленнями англійською: Add, Fix, Change

Підсумок

Що є після третього уроку

Зроблено

  • історія проєкту більше не порожня
  • три стани файлу й дві дії між ними
  • кілька комітів із нормальними повідомленнями
  • одна зміна — один запис

Наступного разу

  • читаємо історію, яку сьогодні створили
  • що саме змінилось у кожному записі
  • порівняння двох версій файлу
  • як повернутись до старого стану
