7.4 Pseudocode · с. 154
⌨️

Псевдокод — і чому стандарту немає

Книжка, 7.4: «any code that is not written on a computer to run. There is no one set pseudocode, because if there was then this would be code with a specific language.»

Тобто

  • Псевдокод не запускають
  • Єдиного стандарту не існує
  • Використовує ключові слова й конструкції, які впізнає будь-який програміст
приклад книжки · с. 154
INPUT Number1 IF Number1 < 10 THEN OUTPUT "too small" ELSE OUTPUT "valid" ENDIF
🔑
Три ключові слова — INPUT, IF, OUTPUT — і цього досить, щоб алгоритм зрозумів будь-хто.
с. 155 · Python · VB.NET · Java
🌐

Один алгоритм — три мови

Той самий алгоритм, три мови — книжка, с. 155. Змінюється запис, не логіка.

Python
number1 = input() if number < 10: print("too small") else: print("valid")
VB.NET
number1 = console.readline() if number < 10 then console.writeline("too small") else console.writeline("valid") endif
Java
number = Integer.parseInt(...); if (number < 10){ System.out.println("too small"); }else{ System.out.println("valid"); }
🔁
Ви писали JavaScript — він у цьому ряду четвертий. Логіка та сама, дужки й крапки з комою різні. Саме тому проєктують у псевдокоді, а не в мові.
⚠️ Важливо · с. 155
⚖️

Присвоєння: = чи ←?

Книжка, с. 155, дослівно: «There are many different valid pseudocode formats. Some will always use capitals for the commands, e.g. INPUT, IF, FOR. Some will use ← instead of an = for assignment.»
І `TIP` там же: «The pseudocode conventions in this book don't always exactly follow the conventions you will see in your exams, but they are still valid. Remember that your syntax doesn't have to be perfect — it is your logic that is important.»

Що це означає на практиці

  • На іспиті ти побачиш ←
  • У цій книжці частіше =
  • Приймають обидва

Що справді оцінюють

Логіку. Чи розбито задачу на кроки, які можна перетворити на програму.

Не бійся, що «синтаксис не той». Бійся, що крок пропущено.

Valid pseudocode

INPUT Value FOR X = 0 to 9 OUTPUT Value + X NEXT X

Invalid pseudocode

PROGRAMMING TASK 7.1 · с. 156
🎲

Гра «вгадай число» — завдання книжки

A computer game stores a number for the user to guess. The user has up to 10 attempts. After each turn the program outputs whether the number they guessed is smaller, larger, or equal to the number they are trying to guess. If they have 10 guesses without getting it correct, tell them what the answer is. If they get it correct, output the number of attempts it took them.

Getting started ★

  • Зіграйте в пару. Обговоріть кроки, які виконуєте
  • Визначте inputs, processes, outputs цієї задачі
  • Пригадайте, з чого складається структурна діаграма

Practice ★★

  • Decompose the system into its subsystems by creating a structure diagram
  • Draw a flowchart for the game
  • Convert your flowchart into pseudocode

Challenge ★★★

  • Is your code efficient? Чи є змінні, які не потрібні? Чи можна скоротити кількість рядків?
  • Amend your program so that each time it runs, a random number is generated
⭐
Рівні Getting started / Practice / Challenge — це рівні самої книжки. Наші ★ / ★★ / ★★★ — те саме.

7.5 Coding · с. 157
💻

Coding — і тестування вже тут

Книжка, 7.5: «Once you have decomposed your problem into subproblems, and you have designed the algorithms using flowcharts and/or pseudocode then you can start writing the program in your chosen programming language. This is often referred to as coding.»

coding

«the writing of a program using one or more programming languages»

Якщо design зроблений — це переклад, а не творчість.

iterative testing

«testing that is carried out while the program is being developed»

Написав одну підпрограму — одразу перевір її різними даними, і лише тоді берись за наступну.

🧩
Ось навіщо була декомпозиція: підпрограму можна перевірити окремо. Ціле недороблене — а частина вже працює й доведена.
7.6 Testing · с. 157
🧪

Що саме доводить тестування

Книжка, 7.6: коли програма готова, треба testing, щоб переконатись, що вона: fully works · does not crash · meets all requirements.
testing
repeated use of a system to try all different possibilities to make sure the system is fully working and cannot be broken
test data
the input data that is used to test a system
🎯
Зверни увагу на третій пункт: meets all requirements. Програма може працювати бездоганно — і не робити того, що просили. Саме тому вимоги записують на етапі analysis.
7.6 · с. 157 · KEY WORDS
🎯

Чотири види тестових даних

ТипОзначення з книжки, дослівно
normaldata that a program should accept
abnormaldata that a program should not accept
extremedata that is on the edge of what is allowed
boundarydata that is on the edge of being accepted, and data that is on the edge of not being accepted
⚠️
Extreme і boundary плутають постійно. Подивись на означення: у extreme одне «edge», у boundary — два, з обох боків межі. Тому boundary завжди пара.
Example 1 · с. 158
📊

Тестові дані для віку 10–100

Requirement: a program allows the user to enter their age as a whole number between 10 and 100 years.
Test data typeExample data — з книжки
Normal Any number between 10 and 100 inclusive, e.g. 10, 20, 50, 100
Abnormal Any data that is not a number between 10 and 100, e.g. 9, −1, 101, 200, "age", "30", 12.2
Extreme The largest number accepted — 100. The smallest number accepted — 10
Boundary Either side of the largest bound — 100 і 101. Either side of the smallest bound — 9 і 10
🔍
Помітили? 100 і 10 стоять і в extreme, і в boundary. Це нормально — і це якраз питання Q13 книжки: «Why can you have the same test data as normal and extreme types of test data?»
Example 2 · с. 158
🔑

Друга таблиця книжки: пароль

Requirement: a user needs to enter a password at least 8 characters long.
Test data typeExample data — з книжки
Normal Any set of 8 or more characters, but they must be text (have speech marks), e.g. "abcdefgh" "12fghj567812"
Abnormal Any set of characters with 7 or less characters, e.g. "1234567" "seven"
Extreme Any with 8 characters only, e.g. "12345678" "ajrkdhJK"
Boundary Either side of the 8 character bound, 7 or 8 characters, e.g. "1234567" "12345678" "abcdefg" "iJHFD7hJ"
🔍
Порівняй із таблицею для віку: там межа числова, тут — довжина рядка. Тип даних змінився, а чотири види тестів ті самі.

SUMMARY · с. 192
📜

Так книжка підсумовує весь розділ

  • Programs are developed by following a program development life cycle.
  • It is made up of; analysis, design, coding and testing.
  • In the analysis stage the problem is identified and decomposed.
  • In the design stage the algorithms are planned.
  • In the coding stage the program is written.
  • In the testing stage the program is tested.
  • Decomposition is the splitting of a system into sub-systems.
  • Decomposition can be shown using a structure diagram.
  • Algorithms can be planned using flowcharts and pseudocode.
  • A linear search checks each item of data in turn.
  • A bubble sort compares the items in pairs repeatedly.
  • Totalling is adding together the values.
  • Counting is adding 1 to the count for each item.
  • To find the minimum, initialise with a large value.
  • To find the maximum, initialise with a small value.
  • Validation is checking data entered is reasonable and within bounds.
  • Checks include; range, length, type, presence, format and check digit.
  • Verification checks that data has been input accurately.
  • Verification checks include visual check and double entry check.
  • Four types of test data are normal, abnormal, extreme and boundary.
  • A trace table is used to dry run an algorithm.
