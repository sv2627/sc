Що ми вже знаємо: уроки 1–8

1
The program development life cycle is made up of; analysis, design, coding and testing.

переклад — клацни

Життєвий цикл розробки програми складається з аналізу, проєктування, написання коду й тестування.
2
Totalling is adding together the values. Counting is adding 1 to the count for each item.

переклад — клацни

Підсумовування — це додавання значень. Підрахунок — це додавання 1 до лічильника за кожен елемент.
3
A linear search checks each item of data in turn.

переклад — клацни

Лінійний пошук перевіряє кожен елемент даних по черзі.
4
A bubble sort compares the items in pairs repeatedly.

переклад — клацни

Сортування бульбашкою раз за разом порівнює елементи парами.
5
Validation is checking data entered is reasonable and within bounds.

переклад — клацни

Валідація — це перевірка, що введені дані розумні й у встановлених межах.
6
Verification checks that data has been input accurately.

переклад — клацни

Верифікація перевіряє, що дані введено точно.
7
A trace table is used to dry run an algorithm. It can be used to find the purpose of an algorithm and to find errors in the algorithm.

переклад — клацни

Трасувальну таблицю використовують для ручного прогону алгоритму. З її допомогою можна знайти призначення алгоритму й помилки в ньому.

Finding the purpose of an algorithm

1
A trace table can help you work out the purpose of an algorithm.

переклад — клацни

Трасувальна таблиця може допомогти зʼясувати призначення алгоритму.
2
By following an algorithm step-by-step you can see what happens to the values, what changes are made, and when these are made.

переклад — клацни

Ідучи за алгоритмом крок за кроком, ви бачите, що відбувається зі значеннями, які зміни вносяться і коли.
3
From this you can determine the purpose of the algorithm.

переклад — клацни

З цього можна визначити призначення алгоритму.
4
First test the algorithm with a set of data that you come up with (if they are not provided for you).

переклад — клацни

Спершу перевірте алгоритм на наборі даних, який ви придумали самі (якщо його вам не дали).
5
Repeat the process with a different set of data.

переклад — клацни

Повторіть процес з іншим набором даних.

Describing an algorithm

1
When you are describing an algorithm you need to do more than repeat the line of code using English statements.

переклад — клацни

Коли ви описуєте алгоритм, треба зробити більше, ніж повторити рядок коду англійськими реченнями.
2
For example, for line 02 don't just say, 'it is a for loop from y is 0 to x.'

переклад — клацни

Наприклад, про рядок 02 не кажіть просто «це цикл for від y = 0 до x».
3
This is stating what each part of the code is, but it does not describe the algorithm.

переклад — клацни

Так ви називаєте, чим є кожна частина коду, але не описуєте алгоритм.
4
You can do a trace table to help you work out the purpose of the algorithm before describing it if that helps you.

переклад — клацни

Можна скласти трасувальну таблицю, щоб зʼясувати призначення алгоритму перед тим, як його описати, якщо це допомагає.

BLine 1 inputs Value1. Line 4 is an IF statement. The last line is an OUTPUT.

Спершу вголос — потім клацни.

1 — B · 2 — A. Інший варіант «is stating what each part of the code is, but it does not describe the algorithm».
