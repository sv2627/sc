Сьогодні

Код перестає бути прямою лінією

Усе, що ви писали досі, виконувалось згори вниз, кожен рядок рівно раз. Сьогодні з'являється розвилка: частина коду виконається, а частина — ні. Залежно від даних.

Пастка

Чому ===, а не ==

У JavaScript є два оператори рівності. Один порівнює чесно, другий спершу «підганяє» типи один під одного — і дає дивні відповіді.

== підганяє типи
'5' == 5 // true 0 == '' // true 0 == false // true null == undefined // true
=== порівнює чесно
'5' === 5 // false 0 === '' // false 0 === false // false 5 === 5 // true
📏
Правило на весь рік: завжди === і !==. Подвійне == просто не використовуємо — так роблять і в реальних проєктах.
🔗
Чому це важливо саме зараз

prompt дає рядок — пам'ятаєте?

script.js
const age = prompt('Вік:'); // ввели 18 if (age === 18) { alert('Рівно 18'); } // не спрацює: '18' !== 18
Забули Number() — і жодна умова з === не спрацює. Помилки не буде, просто нічого не станеться
З > і < гірше: вони самі перетворять рядок на число, тож '18' > 10 дасть true. Частина умов працює, частина ні
Тому Number() ставимо одразу в тому ж рядку, що й prompt
🤔
Передбач

П'ять порівнянь

консоль
console.log('7' === 7); console.log('7' > 3); console.log(10 >= 10); console.log(Number('7') === 7); console.log(2 < 5 < 1);

Останній — не помилка. Але відповідь дивна

Назви всі п'ять, потім клацни.

1. false — різні типи

2. true — > сам перетворив рядок на число

3. true — «або дорівнює»

4. true — тепер обидва числа

5. false — і це найцікавіше. Рахується злíва направо: 2 < 5 дає true, далі лишається true < 1. true перетворюється на 1, отже 1 < 1 — false

Мораль: подвійні нерівності a < b < c у JavaScript не працюють як у математиці. Пишемо через && — за десять хвилин.

Нове в коді

else — друга гілка

script.js
if (age >= 18) { alert('Повнолітній'); } else { alert('Неповнолітній'); }
else не має власної умови. Це «у всіх інших випадках»
Виконається рівно одна з двох гілок. Ніколи обидві й ніколи жодної
else пишеться на тому ж рядку, де закрилась фігурна дужка if. Це не обов'язково, але так прийнято
🔀
Два окремі if і if…else — різні речі. Два if перевіряються обидва, і можуть спрацювати обидва.
🪜

Приклад цілком

Квиток у кіно — робочий код

script.js
const age = Number(prompt('Скільки вам років?')); let price; let kind; if (age < 6) { price = 0; kind = 'малюк'; } else if (age < 18) { price = 80; kind = 'дитячий'; } else if (age < 60) { price = 150; kind = 'дорослий'; } else { price = 100; kind = 'пенсійний'; } alert(`Квиток ${kind}: ${price} грн`);
let, а не const: значення присвоюється пізніше й залежить від гілки. const тут дав би помилку
🔧
Виправ

Тут дві гілки мертві

script.js
if (age < 60) { price = 150; } else if (age < 18) { price = 80; } else if (age < 6) { price = 0; } else { price = 100; }

Які гілки не спрацюють ніколи і чому?

Знайди сам, потім клацни.

Мертві — друга й третя.

Будь-який вік, менший за 18, автоматично менший за 60. Отже перша гілка забирає його собі, і до другої черга не доходить ніколи.

Те саме з третьою: усе, менше за 6, менше і за 60.

Фактично цей код має дві робочі гілки: до 60 → 150 ₴, решта → 100 ₴.

Лікується перестановкою: найвужча умова — першою. Жодної помилки в консолі при цьому не було.

&& — обидві умови разом

Читається «і». Дає true тільки тоді, коли обидві частини істинні.

script.js
// саме так пишеться 18–22 if (age >= 18 && age <= 22) { alert('Студентський'); }

18 <= age <= 22 — так не можна. Помилки не буде, результат безглуздий

Нове в коді

|| — досить однієї

Читається «або». Дає true, якщо істинна хоча б одна частина. Символ набирається двічі тією ж клавішею, що й \, із Shift.

Передбач

Хто пройде на атракціон?

script.js
// зріст ≥ 140 І вік ≥ 12 if (height >= 140 && age >= 12) { alert('Можна'); } else { alert('Не можна'); } // А · height 150, age 10 // Б · height 130, age 15 // В · height 160, age 12 // Г · height 140, age 12

Хто з чотирьох пройде?

Розбери всіх чотирьох, потім клацни.

А — не можна. Зріст ок, вік ні. && вимагає обидва

Б — не можна. Вік ок, зріст ні

В — можна. Обидва ок

Г — можна. Рівно на межі, а >= це «або дорівнює»

Випадок Г — найчастіша помилка в реальних задачах. Поставили б > замість >= — і людину зростом рівно 140 не пустили б. Межі перевіряємо завжди окремо.

Обіцяне минулого разу

Нарешті можна перевірити ввід

На уроці 2 ми бачили, як NaN і null тихо руйнують розрахунок. Тепер є чим їх зловити.

script.js
const raw = prompt('Вік:'); const age = Number(raw); if (raw === null) { alert('Ви скасували'); } else if (raw === '') { alert('Поле порожнє'); } else if (Number.isNaN(age)) { alert('Це не число'); } else { alert(`Вік: ${age}`); }
⚠️
age === NaN — не працює. NaN не дорівнює навіть сам собі. Перевіряти тільки через Number.isNaN().
📐
Культура коду

Вкладені if проти &&

Сходи вниз
if (age >= 18) { if (hasTicket) { if (!isBanned) { alert('Заходьте'); } } }
Один рядок
if (age >= 18 && hasTicket && !isBanned) { alert('Заходьте'); }
Правило: якщо всі вкладені if ведуть до однієї дії — це &&. Вкладеність потрібна тільки тоді, коли на кожному рівні є свій else
🪤
Пастка, яку побачите сьогодні

Одне = замість трьох

script.js
let age = 10; if (age = 18) { // ← одне = alert('Повнолітній'); } // покаже «Повнолітній» // і зіпсує age назавжди
Одне = — це присвоєння, а не порівняння. Умова стає «поклади 18 у age, і візьми результат»
Результат присвоєння — саме значення, 18. Для if це істина: будь-яке число, крім нуля, вважається true
Тому умова спрацює завжди, хай який був age. І змінна ще й зіпсується
🔎
Ознака: гілка спрацьовує щоразу, незалежно від даних. Побачили таке — першим ділом рахуйте знаки рівності в умові.

Діагностика

П'ять бід сьогоднішнього уроку

Умова не спрацьовує ніколи — забули Number(), порівнюєте рядок із числом через ===
Умова спрацьовує завжди — одне = замість ===
Гілка не спрацьовує ніколи — вище стоїть ширша умова, яка забирає всі випадки
Спрацювали дві гілки — написали два окремі if замість else if
Діапазон поводиться дивно — написали 18 <= age <= 22 замість &&
Спільне в усіх п'яти: жодного червоного рядка в консолі

Виправ

Чотири рядки — чотири різні біди

script.js
const age = prompt('Вік:'); if (age === 18) { … } if (age = 18) { … } if (18 <= age <= 22) { … } if (age >= 18); { … }

Що не так у кожному?

Розбери всі чотири, потім клацни.

1. Немає Number() — порівнюється '18' з 18, завжди false

2. Одне = — умова завжди істинна

3. Подвійна нерівність — треба age >= 18 && age <= 22

4. Крапка з комою після дужки — тіло if порожнє, а блок у фігурних дужках виконається завжди, сам по собі

Четверта — найпідступніша: око її не помічає, а поводиться вона як друга.

Закінчив раніше?

Банк завдань — бери будь-яке

Оцінка за балами. 0–59 → «незадовільно», 60–74 → «задовільно», 75–89 → «добре», 90–100 → «відмінно»
Парне чи непарне. Спитати число й сказати, яке воно. Знадобиться % — остача від ділення
Найбільше з трьох. Спитати три числа й назвати найбільше. Без масивів, тільки умови
Пароль. Спитати пароль. Прийняти, тільки якщо довжина .length не менша за 8
Пора року. Спитати номер місяця (1–12) і назвати пору року. Перевірити, що число в межах
Високосний рік. Ділиться на 4, але не на 100, або ділиться на 400. Три умови в одному виразі
Усі шість робляться тільки тим, що було сьогодні. Нічого нового шукати не треба
